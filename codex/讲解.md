## 1. 任务是什么

这是一个**三分类问题**：输入是一行问卷回答，输出是这一行描述的运动：

```text
Baseball / Basketball / Soccer
```

例如，一行回答说“容易入门、冬天也能玩、通常在室内、联想到橙色”，模型要综合这些信息，判断它更像哪项运动。

数据的结构很重要：**870 行 = 290 个人 × 3 种运动**。同一个人对三种运动各回答一次。这些行并不完全独立，因为它们共享回答者的用词、打分和偏好。

每行有 **12 个问题的答案**，另外有 `id` 和 `label`：

- `id`：回答者编号，只用来分组。
- `label`：正确的运动类别，是训练目标。
- 12 个问题的答案：模型真正可以使用的输入。

老师最终会用另外收集的 TA / instructor 回答测试模型。我们自己留出的 test，只是本地的最终检查集，不是老师隐藏的那个 test。

## 2. 为什么按“人”划分数据（参考 rubric 的数据划分项）

`code/data.py` 先把 respondent ID 排序，再用随机种子 `311` 打乱，分成：

| 集合 | 人数 | 行数 | 用途 |
|---|---:|---:|---|
| Train | 202 | 606 | 数据探索、拟合预处理、交叉验证调参 |
| Validation | 44 | 132 | 各模型调好参数后，比较模型家族 |
| Local test | 44 | 132 | 最终锁定方案后，只评估一次 |

代码的顺序是先取 44 个 ID 做 test，再取 44 个做 validation，剩余做 train。每个人的三行始终在同一个集合。

**为什么不按行随机分？** 假设张三的 Baseball 回答在 train，Soccer 回答在 test。模型可能利用张三特有的用词和打分习惯，得到比面对陌生回答者更高的分数。我们真正关心的是对新回答者的泛化能力，因此要把张三的全部回答放在一起。

**为什么只在 train 上做探索？** 看图、比较类别均值、决定怎样编码，都可能影响模型设计。提前根据 test 里的规律改方案，就已经把 test 的信息用于开发，最后的分数不再是独立检查。

**为什么 `id` 不能当特征？** 它是一个编号，不是运动的属性。模型记住某些 ID，不代表学会了识别运动。代码明确只取 `FEATURES` 中的 12 个问题，不把 ID 或 label 编进特征矩阵。

**为什么每类都是 202 行？** 训练集有 202 个人，每个人对三种运动各答一次，所以每类恰好 202 行。现在没有类别不平衡问题，不需要为了“平衡”再重复抽样或给某一类加权。

具体每一行属于哪个集合，都记录在 `analysis/split_manifest.csv`。不要看过分数后换随机种子寻找更好看的划分。

## 3. 每个特征是什么类型，怎么处理（参考 rubric 的特征与预处理项）

| 特征 | 类型 | 处理方式 | 为什么 |
|---|---|---|---|
| Ease（0–10） | 数值 | 检查范围 → 缺失填补 → 标准化 | 保留数值大小和距离 |
| Strategy / Injury / Individual | 五级 Likert | 转成 1–5 → 填补 → 标准化 | 用一个数保留等级顺序 |
| Venue / Season / Music | 多选 | multi-hot，每个选项一列 | 一个回答可以同时选择多个选项 |
| Food / Colour / Song / Feeling | 自由文本 | 每道题分别做 TF-IDF，包含单词和相邻双词 | 把不同词语提供的证据变成数值 |
| Price | 用文本表达的金额 | 解析 → 训练分位数封顶 → `log(1+x)` → 填补 → 标准化 | 处理写法不同、缺失和右偏分布 |

每个原始问题还加一个“是否缺失”的 0/1 指示列，包含无法解析成数字的情况。

### 标准化是什么

$$
x' = \frac{x-\mu}{\sigma}
$$

- $\mu$：拟合用的训练部分的均值。
- $\sigma$：同一部分的标准差。

例如，金额可能是几百，Likert 只有 1–5。对 KNN 来说，直接计算距离时，金额的大数值可能盖过其他信息。标准化可以避免单纯由单位不同决定距离大小，也有助于梯度优化和 L2 正则化。

**决策树通常不需要这种缩放**：把价格从美元换成百美元，不会改变价格从小到大的顺序，树仍然可以用对应阈值切分。为了统一输入流程，这版森林也接收经过缩放的数值列。

二进制 multi-hot、缺失指示列和已经按文本块归一化的 TF-IDF，不再做这种逐列标准化。

### 为什么 Likert 用 1–5

```text
Strongly disagree → 1
Disagree          → 2
Neutral           → 3
Agree             → 4
Strongly agree    → 5
```

优点是保留顺序、列数少。代价是模型会把 1→2 和 4→5 当成相同大小的变化，但人的态度不一定真的等距。One-hot 可以避免这个等距假设，却要更多列；目前计划选择 ordinal 编码。

### Multi-hot 是什么

假设 Season 的选项顺序是 `[winter, spring, summer, fall]`：

```text
"Spring,Summer" → [0, 1, 1, 0]
```

这和只能激活一个位置的 one-hot 不同。每个选项都可以独立为 1。

代码按逗号拆分、统一大小写、去掉重复选项。Music 的 `No particular type` 是一个有效选项，不能因为“没有特别喜欢的类型”就把它误当成缺失。

### TF-IDF 是什么

先用训练回答建立词表，再把每条回答变成数值向量。和只记录“出现 / 没出现”的 0/1 编码相比，TF-IDF 还考虑：

1. **TF**：一个词在这条回答里出现了多少次。
2. **IDF**：这个词在整个训练语料里有多常见。到处都出现的词通常没有那么独特。

代码采用的归一化前权重是：

$$
w_{t,d}=(1+\log \mathrm{tf}_{t,d})
\left(1+\log\frac{1+n}{1+\mathrm{df}_t}\right),
\qquad \mathrm{tf}_{t,d}>0.
$$

其中 $n$ 是当前拟合部分的回答数，$\mathrm{df}_t$ 是包含词 $t$ 的回答数。没出现的词权重为 0。

例如，`waka` 如果只在少数相关回答里出现，它可能比很多回答都有的普通词更有区分力。之后再对每一条回答的文本向量做 L2 归一化，让长回答不至于只因为字多就得到很大的向量长度。

当前设置：

- **每道题各自一个词表**：Colour 中的 `blue` 和 Song 中的 `blue` 是不同列。
- **Unigram + bigram**：既看单词，也看 `hot dog`、`take me` 这样的相邻双词。
- **默认 `min_df=2`**：至少出现在两个训练文档里才保留。
- **每道题最多 500 个词项**：限制维度。
- 统一 Unicode、大小写和空白，移除 `[this sport]` 这类匿名占位符，向量化时去除重音差异。
- 没有做词干化、同义词合并或统一单复数；例如 `hotdog` 不会自动等于 `hot dog`。
- 预测时遇到词表里没有的词，直接忽略，不临时增加新列。

默认处理后共有 **1,389 列**：

```text
5 个数值 + 12 个缺失指示 + 21 个多选选项 + 1,351 个文本词项
= 1,389
```

矩阵只有约 **2.24%** 的位置非零，所以使用稀疏矩阵存储。606 行对应 1,389 列，也说明我们需要限制模型复杂度。

## 4. 缺失值、异常值、不一致的数据（参考 rubric 的数据质量项）

### 缺失不只是空白

代码把空字符串、`n/a`、`none`、`-`、`unknown` 等明确的缺失或未知标记统一处理。

训练集中的主要缺失率是：

| 特征 | 缺失或不可用比例 |
|---|---:|
| Food | 2.64% |
| Colour | 0.99% |
| Song | 10.56% |
| Feeling | 0.50% |
| Price 原始缺失标记 | 1.65% |
| Price 加上无法可靠解析的回答 | 13.04% |

**最后两行为什么不一样？** 有些人填了文字，因此不算原始空缺，但这段文字不能可靠地转成金额。例如 `very willing` 没说明愿意花多少钱。不能把“填了东西”当成“有可用数值”。

Song 的缺失率在 Baseball / Basketball / Soccer 中分别约为 **15.8% / 11.9% / 4.0%**。这提示缺失本身可能带有类别信息，所以要保留 missing indicator。但这种现象不能证明缺失的原因，更不能确定它是否随机发生。

数值缺失使用**当前拟合部分的中位数**填补；文本缺失使用空文本，同时保留缺失指示。交叉验证时，中位数不能提前用整个 train 算好后分给每一折。

### Price 为什么要保守解析

`code/features.py` 的 `parse_price` 有明确规则，例如：

| 原回答示例 | 解析结果 |
|---|---:|
| `$1,000` | 1000 |
| `CAD 150` | 150 |
| `$150-$250` | 200，取区间中点 |
| `Nothing` / `Not willing` | 0 |
| 单独的 `none` | 缺失，含义有歧义 |
| `USD 100` / `1€` | 缺失，不猜汇率 |
| `very willing` | 缺失，没有金额 |
| `200 or 500 depending on game` | 缺失，不擅自选择一个金额 |

当前解析器主要接受完整的金额表达和简单范围，不是从所有长句里随便抓一个数字。这样会少用一些回答，但能避免把评分量表、多个情境或其他数字误当金额。默认把未标明币种的金额与 CAD 放在同一尺度，这是一个建模假设。

最终有 **79/606** 个金额无法使用，占 13.04%。

### 为什么不直接删除异常高的价格

可解析价格的训练统计是：中位数 **100**，均值 **226.50**，最高 **10,000**，IQR 为 **50–225**。均值明显高于中位数，说明右侧有长尾。

用 1.5-IQR 规则会标出 67 个价格。它们值得检查，但这个规则不能证明答案填错；有人确实可能愿意花很多钱。

目前处理是：

```text
解析金额
→ 上限设为当前拟合部分的第 99 百分位
→ log(1+x)
→ 用变换后的训练中位数填补缺失
→ 标准化
```

在完整训练部分算出的第 99 百分位是 **1,870**。例如 10,000 先变成 1,870，再取对数。交叉验证时，每一折会重新学习自己的上限，不能固定使用根据全部训练行算出的 1,870。

`log(1+x)` 把大数之间的距离压缩：100 和 1,000 原本相差 900，变换后约为 4.62 和 6.91。加 1 是为了让价格为 0 时也能计算。

## 5. 哪些特征有预测力

### 数值：比较类间差距与类内波动

Ease 的训练均值：

| 类别 | 均值 | 标准差 |
|---|---:|---:|
| Baseball | 4.02 | 2.05 |
| Basketball | 6.03 | 2.12 |
| Soccer | 6.16 | 2.35 |

Baseball 与另外两类有大约 2 分的均值差，但各类内部的标准差也有约 2 分。所以 Ease 有帮助，却不能靠一个阈值把所有答案分对。

### 多选：比较每个类别选某选项的比例

Indoor facility 的选择率是：

```text
Baseball 23.3% / Basketball 96.5% / Soccer 63.4%
```

这是很强的差异；但 Soccer 也有不少回答选择室内，所以“室内 = Basketball”不是必然规律。Winter、Hip-hop 等选项也为 Basketball 提供额外证据。

### 文本：比较词项出现率

按 Baseball / Basketball / Soccer 的顺序：

- Colour 中的 `green`：约 **3.0% / 0% / 55.0%**。
- Colour 中的 `orange`：约 **2.0% / 52.0% / 0.5%**。

`analysis/text_associations.csv` 还提供训练集上的卡方关联分数，用来查看值得关注的词项。**这不是模型准确率，也不是已经做过多重比较校正的显著性结论。**

## 6. 三个模型和选它们的理由（Methodology 的模型选择项）

### 1. Softmax 回归 + L2 正则化

可以把它理解为：**不同特征分别给三种运动加分，最后把分数变成概率。**

$$
z_k=\mathbf{w}_k^\top\mathbf{x}+b_k,
\qquad
p(y=k\mid\mathbf{x})=\frac{e^{z_k}}{\sum_j e^{z_j}}.
$$

例如 `orange`、`winter`、`indoor facility` 都可能给 Basketball 增加证据。模型会通过训练学习这些权重，而不是由我们手动指定。

1,389 个特征只对应 606 行、202 位独立回答者。权重太自由容易记住偶然词语，因此加 L2 惩罚来限制过大的权重。可以概念性地写成：

$$
\text{交叉熵损失}+\frac{\lambda}{2}\|W\|_F^2.
$$

代码用 `C` 控制正则化强弱：**C 越小，正则化越强**。优化器是 L-BFGS，不是 SGD；最多 3,000 次迭代，容差 `1e-5`。这版没有学习率计划或 early stopping。

### 2. 随机森林

树可以学习“满足某个条件后，再看另一个条件”的规则。例如先判断是否选择室内，再结合季节和入门难度。它适合表示特征之间的非线性关系。

一棵树容易记住训练数据；森林训练很多棵有随机差异的树，再合并它们的类别概率，降低对某一棵树的依赖。

本版固定 **200 棵树**，使用 bootstrap 和 Gini impurity，再调树深度、叶子最少样本数和每次分裂考虑的特征数量。它不通过梯度下降训练，所以没有 learning rate。

### 3. KNN

KNN 的思路是：把新回答变成特征向量，找训练数据中距离最近的 $k$ 条回答，再根据邻居的类别投票。

- `k` 小：很依赖附近少量样本，容易受噪声影响。
- `k` 大：更平滑，但可能把不同类别混在一起。
- 可以让每个邻居权重一样，也可以让更近的邻居权重更大。

课程提供了 KNN baseline，因此把它作为不同思路的比较对象。它的风险是：高维稀疏文本中的距离可能不够有意义，而且不同特征块的大小会影响距离。

**我们现在没有比较分数来证明 KNN 比另外两个模型好或差。** 选入它，是为了检验“相似回答是否倾向于同一运动”这个假设。完整模型选择要等三个家族都调参之后。

### 具体调哪些参数

| 模型 | 初始搜索范围 | 配置数量 |
|---|---|---:|
| Softmax | C：0.001、0.01、0.1、1、10、100；四个文本块共同的 min_df：1、2、3、5 | 24 |
| Forest | 最大深度：3、6、12、不限；叶子最小样本数：1、3、8；每次分裂特征数：平方根或 30% | 24 |
| KNN | k：3、5、9、15、25、41；uniform / distance；Manhattan / Euclidean | 24 |

每个配置做 5 折，所以初始共有 **3 × 24 × 5 = 360 次交叉验证拟合**，还不包括选出最佳配置后的重拟合。这是计划中的数量，不代表这些实验已经运行。

如果最优值落在搜索边界，比如最大的 C 仍最好，应根据训练折结果考虑扩大范围。`models.py` 实现初始网格，边界判断和扩展需要记录后再做。

## 7. 验证方案（Methodology 的验证与公平比较项）

### 第一层：在 train 内做分组交叉验证

把 202 位训练回答者分成 5 折。每次用其中 4 折训练，剩下 1 折评分，重复 5 次。

这里用 `StratifiedGroupKFold`，种子 311，同时考虑类别比例和 respondent 分组。最重要的限制仍然是：**同一个人的三行不能跨折。**

每一折都重新学习：

```text
价格上限
数值中位数
标准化均值与标准差
多选选项词表
四个文本词表与 IDF
```

如果先对全部 606 行拟合 TF-IDF，再做 5 折，评分折的词语分布就已经进入训练过程。这正是把预处理放进 `Pipeline` 的原因。

### 第二层：三个家族都调好，再比较 validation

每个家族先按平均 CV macro-F1 选自己的配置。之后再在 132 行 validation 上各评估一次。

计划的选择规则是：最高 validation macro-F1 优先；如果与最高分相差不超过 **0.01（一个百分点）**，则按 Softmax → KNN → Forest 的顺序偏好更易部署的方案。这是事先设定的操作规则，不代表差一点就能统计上断定哪个模型更强。

**为什么不能只调看起来最好的那个？** 默认参数对不同模型的适合程度不同。如果只有 Softmax 得到认真调参，另外两个一直用默认值，比较就混入了调参投入的差别。

同样，给每个模型 24 个配置只是明确了初始预算，不意味着三个搜索范围已经同样充分。

### 第三层：方案锁定后，再看 local test

选好模型和预处理以后，用 train + validation 重新拟合，然后在 local test 上评估一次。

这样训练数据变多，但 validation 已经用于最后拟合，不能再充当独立检查集。不能看见 test 分数不满意，就继续调参，再把同一 test 当作“首次测试”。

老师隐藏的数据来自不同回答者群体，即使本地 test 分数不错，也不能保证相同的隐藏测试成绩。最终报告的预测准确率需要之后用真实实验支持。

## 8. 评估指标（Methodology 的指标项）

对某一类别 $k$，把它看成“这一类”和“其他类”：

- $TP_k$：实际是 $k$，也预测成 $k$。
- $FP_k$：实际不是 $k$，却预测成 $k$。
- $FN_k$：实际是 $k$，却被预测成其他类。

$$
P_k=\frac{TP_k}{TP_k+FP_k},\qquad
R_k=\frac{TP_k}{TP_k+FN_k},\qquad
F1_k=\frac{2P_kR_k}{P_k+R_k}.
$$

例如，模型预测了 10 条 Basketball，其中 8 条正确；数据实际有 20 条 Basketball。那么：

```text
Precision = 8/10 = 0.8
Recall    = 8/20 = 0.4
F1        = 2×0.8×0.4/(0.8+0.4) ≈ 0.533
```

这是说明公式的小例子，不是本项目已经得到的实验结果。

**Macro-F1** 把三类 F1 平均：

$$
\mathrm{Macro\text{-}F1}=\frac{F1_{Baseball}+F1_{Basketball}+F1_{Soccer}}{3}.
$$

每项运动的权重相同，可以暴露“某一类几乎完全不会分”的问题。Weighted-F1 则按类别样本数加权，类别不平衡时可能更受大类表现影响。

如果永远预测 Soccer，在当前平衡训练集上：

- Accuracy = 1/3。
- Soccer precision = 1/3，recall = 1，F1 = 1/2。
- 另外两类 F1 = 0。
- Macro-F1 = `(0.5+0+0)/3 = 1/6 ≈ 0.167`。

因此计划用 **macro-F1 做主要选择指标**，同时报告 accuracy、逐类 precision / recall 和混淆矩阵。混淆矩阵的行是真实类别，列是预测类别。

### 修改代码或分析后，记得更新提交包

`code.zip` 是生成时的快照，不会随着源文件编辑自动更新。修改代码、重新生成分析并确认正文数字一致后，可以在 `codex/` 目录用下面的命令重新打包：

```sh
python3 - <<'PY'
from pathlib import Path
from zipfile import ZipFile, ZIP_DEFLATED

with ZipFile('code.zip', 'w', ZIP_DEFLATED) as z:
    for folder in ('code', 'analysis'):
        for p in sorted(Path(folder).rglob('*')):
            if p.is_file() and '__pycache__' not in p.parts and p.suffix != '.pyc':
                z.write(p, p.as_posix())
    for name in ('README.md', 'requirements.txt', 'REQUIREMENTS_CHECK.md'):
        z.write(name)
PY
```

这只打包代码与分析证据，不会把原始 `data/` 或 `.venv/` 放进去。中文讲解是帮助理解的配套文件，不属于必须上传的两个文件。
